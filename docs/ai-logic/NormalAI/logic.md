# NormalAI 决策逻辑

## 概述

NormalAI 使用 **CFRU 评分系统** 进行招式选择，综合考虑伤害、状态招式、强化招式的价值。

**难度**: Normal / Smart
**适用场景**: 道馆馆主、普通训练家

---

## 决策流程

```
收到请求
    │
    ▼
构建战斗状态 (BattleState)
    │
    ▼
获取可用招式
    │
    ├─ 无可用招式 → 尝试切换或挣扎
    │
    └─ 有可用招式
            │
            ▼
        评估是否应该切换
            │
            ├─ 应该切换 → 选择最佳换入
            │
            └─ 不换人
                    │
                    ▼
                为所有招式评分
                    │
                    ▼
                选择得分最高的招式
```

## 评分系统

### 评分公式

```
最终得分 = 100 + 负面调整 + 正面调整
```

每个招式从 **100 分** 开始，根据各种因素加减分。

`FIRST` 根据当前招式与对手已知招式、preset 候选的优先度及速度估计，包含恶作剧之心等优先度修正；它不读取对手本回合的选择。自爆、大爆炸、薄雾炸裂等使用后倒下的招式不获得“两击击杀”奖励，能够一击击杀时仍获得击杀奖励。

### 评分流程

```
基础分 100
    │
    ▼
负面评分 (扣分)
    │ - 免疫检查 (-100)
    │ - 被抵抗 (0.5x: -5, 0.25x: -20)
    │ - 低伤害 (<10%: -20, <20%: -8, <33%: -3)
    │ - 状态招式失效 (-10~-20)
    │ - 强化满级 (-100)
    │ - 回复浪费 (-3~-8)
    │
    ▼
正面评分 (加分)
    │ - 击杀奖励 (+20~+28)
    │ - 高伤害 (+2~+10)
    │ - STAB (+3)
    │ - 克制 (+4~+8)
    │
    ▼
最终得分
```

## 伤害计算

出招、先手击杀和承伤评估按当前格式的 Dex 读取招式威力、属性和分类。Gen5／PokeMMO 的拍落为 20 威力，不享受现代规则的持道具威力加成。制裁光砾、多属性攻击和高科技光炮根据当前道具解析属性，评分与伤害计算使用同一结果，并考虑道具失效。

### 完整公式

```
基础伤害 = ((2×等级/5+2) × 威力 × 攻击/防御) / 50 + 2
最终伤害 = 基础伤害 × STAB × 属性克制 × 其他修正
```

### 考虑的因素

| 类别 | 内容 |
|------|------|
| 能力值 | 攻击/防御 + 能力变化阶段 |
| 攻击方特性 | 大力士、活力、铁拳、技师等 |
| 防御方特性 | 厚脂肪、耐热、水泡等 |
| 道具 | 讲究头带/眼镜、生命宝珠等 |
| 天气 | 晴天火+50%/水-50%，雨天相反 |
| 地形 | 电气/草地/精神场地 +30% |

### HP 相关威力与伤害

招式选择使用当前请求中的己方 HP 和公开追踪的对手 HP。换入并承伤后的下一次决策按剩余 HP 计算，不预测换入前的未来状态。

| 招式 | 计算依据 |
|------|----------|
| Water Spout / Eruption / Dragon Energy | 使用者当前 HP 比例 × 150，取整且至少为 1 |
| Flail / Reversal | 使用者 HP 越低威力越高，按模拟器分段计算 20／40／80／100／150／200 |
| Crush Grip / Wring Out / Hard Press | 目标当前 HP 比例，前两者最高 120、Hard Press 最高 100，采用模拟器的定点取整规则 |
| Brine | 目标 HP 不超过一半时威力翻倍为 130 |
| Super Fang / Nature's Madness / Ruination | 目标当前 HP 的一半，向下取整且至少为 1 |
| Guardian of Alola | 目标当前 HP 的 75%；已知保护状态下另行减伤 |
| Endeavor / Final Gambit | 双方当前 HP 差值／使用者当前 HP |

静态 `basePower: 0` 的攻击招式先解析动态威力，再判断是否无伤害。伤害缓存键包含双方当前 HP 和最大 HP，HP 变化后不复用旧伤害结果。威力计算及分段边界通过 `test/server/npc/hp-dependent-damage.js` 与模拟器回调对照验证；实战用例覆盖吼鲸王换入承伤后选择 Surf 而不是高估 Water Spout。

### 对手能力值估算

AI 无法直接获取对手的个体值 (IV)、努力值 (EV) 和性格，使用以下默认值：

| 参数 | 值 | 说明 |
|------|-----|------|
| IV | 31 | 满个体值 (竞技标准) |
| EV | 85 | 平均努力值 (510/6 ≈ 85) |
| 性格 | 中性 | 不应用性格修正 |

**示例 - 胡地速度估算**:
```
基础速度 = 120
估算速度 = floor((floor((2×120 + 31 + floor(85/4)) × 50 / 100) + 5) × 1.0)
         = floor((floor(292 × 50 / 100) + 5))
         = floor(146 + 5) = 151
```

> 实际胡地 (Timid, 252 Spe) 速度为 189，估算值偏低但可用于基础判断。

|------|-------------------|
| 普通 | 3 次 |
| Skill Link | 5 次 |
| Loaded Dice | 4.5 次 |

### 重量招式

某些招式的威力取决于精灵体重：

**Low Kick / Grass Knot** (根据目标体重)

| 体重 | 威力 |
|------|------|
| ≥ 200kg | 120 |
| ≥ 100kg | 100 |
| ≥ 50kg | 80 |
| ≥ 25kg | 60 |
| ≥ 10kg | 40 |
| < 10kg | 20 |

**Heavy Slam / Heat Crash** (根据体重比: 攻击方/防御方)

| 体重比 | 威力 |
|--------|------|
| ≥ 5 | 120 |
| 4 | 100 |
| 3 | 80 |
| 2 | 60 |
| ≤ 1 | 40 |

**体重修正**:
- Light Metal: 体重减半
- Heavy Metal: 体重翻倍
- Float Stone: 体重减半

### 额外伤害 (回合结束)

在评估击杀能力时会考虑回合结束的额外伤害：

| 来源 | 伤害 |
|------|------|
| 普通毒 | 1/8 最大 HP |
| 剧毒 | 递增 (counter/16 最大 HP) |
| 灼伤 | 1/16 最大 HP |
| 沙暴 | 1/16 最大 HP (非岩/地/钢) |
| 冰雹 | 1/16 最大 HP (非冰) |
| 寄生种子 | 1/8 最大 HP |
| Salt Cure | 1/8 最大 HP (水/钢系: 1/4) |

**免疫条件**:
- Magic Guard 免疫所有额外伤害
- Poison Heal 不受毒伤害
- 岩/地/钢类型免疫沙暴
- 冰类型免疫冰雹
- Sand Veil/Ice Body/Safety Goggles 免疫天气伤害

### 击杀判断

```
能击杀 = 最大伤害 >= 对手当前 HP
保证击杀 = 最小伤害 >= 对手当前 HP
```

出招时，若多个本回合可生效的攻击招式都能以平均伤害击杀同一目标，优先命中率更高的招式，命中率相同再比较原评分。有确定先手击杀的招式时，在这些招式中比较可靠性。比较包含天气对雷电／暴风／暴风雪的命中率影响，以及无防守；评分日志记录因此产生的扣分。换人判断仍不考虑命中率。

天气在共享状态入口统一为 `sun`、`rain`、`sand`、`hail`、`snow` 等标识，供伤害、速度和招式评分使用。

单打、双打和 Multi 共用公开状态入口，`field.formatId` 将赛制传入规则计算。`util/mechanics.ts` 负责有效道具、落地状态、特性绕过和实际优先度；`util/type-calc.ts` 的 `getMoveInteraction` 统一判定属性、特性和精神场地免疫。出招评分、伤害估算、换人威胁与范围招式的队友伤害使用这些结果。Normal 与 Hard 共用行动顺序规则，分别保留各自的策略评分。

实际优先度区分第六世代疾风之翼与后续世代的满血限制。速度估算考虑赛制的麻痹倍率、道具失效和公开的古代活性／夸克充能速度强化。

Rest 的固定睡眠计数只依赖公开的成功施放记录和 `cant|slp` 行动记录，并考虑早起特性与格式的换人规则。可确定本回合醒来时，Sleep Talk／Snore 扣 100 分并标记无效；未睡眠时同样处理。普通催眠的随机剩余回合保持未知。

## 负面评分 (扣分)

### 免疫 (-100)

| 情况 | 扣分 |
|------|------|
| 属性免疫 (地面 vs 飞行) | -100 |
| 神奇守护 (非克制) | -100 |

### 特性免疫 (-100)

属性、吸收特性、神奇守护、隔音、防弹及优先度阻挡确认生效时，招式扣 100 分、标为无效并停止正向加分。判定考虑破格类特性、特性护具、道具失效及落地状态；重力不会消除食土的吸收效果。双打与 Multi 的优先度阻挡同时检查目标的存活队友。

| 特性 | 免疫属性 |
|------|---------|
| 蓄电/引雷/电气引擎 | 电 |
| 储水/引水/干燥皮肤 | 水 |
| 引火 | 火 |
| 食草 | 草 |
| 飘浮/食土 | 地面 |

对手特性通过 `BattleTracker.handleAbilityEvent` 统一追踪。`-ability`、`-immune`、`-heal`、`-damage`、`-start`、`-activate`、`-fail`、`-weather`、`-fieldstart` 都能暴露特性；`-status`、`-block` 和 `cant` 中的特性来源也按事件语义处理。天气、场地和 HP 的记录与特性记录分别更新。

特性归属依赖具体事件：吸收回血的持有者是回血精灵，`[of]` 可能指攻击者；反伤、天气和场地消息通过 `[of]` 指明持有者；款待和芳香幕等队友效果属于施加效果的精灵，不能记给受益者。未暴露的特性保持未知，不从道具名、招式名或缺失的来源字段猜测持有者。物种只有一种特性时沿用物种推断。

`ability` 表示当前特性，`baseAbility` 保存原始特性。Trace、Role Play、Skill Swap、Mummy 等临时变化不覆盖原始记录，`-endability` 清除当前生效的特性；换下再上场时恢复已知原始特性，原始特性未知时仍保持未知。己方 Trace／Role Play 复制对手特性时，公开消息也用于记录对手的被复制特性。追踪结果用于伤害计算、招式评分和换人判断；公开信息的准确性独立于决策策略的强弱。

公开 `-transform` 消息记录复制时的物种、属性、能力变化和目标状态。非 HP 能力值、招式与特性根据复制目标估计；复制己方时可使用自己的 request，复制对手时仅使用公开信息和先验。变身者保留自己的 HP、等级和道具，变身期间使用的招式不写入原始配招；换下后清除复制状态。

例如，讲究围巾多边兽-Z 锁定十万伏特，电灯怪触发蓄电后，AI 将十万伏特视为无效招式；在未被困住且存在评分合适的替补时主动换人。特性尚未暴露时，不将所有电灯怪直接视为蓄电。

### 魔法镜 (-20)

对有魔法镜特性的对手使用可被反弹的招式 (隐形岩、鬼火等)。

### 状态招式失效 (-10~-20)

| 情况 | 扣分 |
|------|------|
| 对手已有该状态 | -10~-15 |
| 对手属性免疫 (电系免疫麻痹) | -20 |
| 对手特性免疫 (不眠免疫睡眠) | -20 |
| 对已困倦目标再次使用哈欠 | -20 |

恶作剧之心强化的变化招式若被对手的恶系免疫，扣 100 分并标记无效，总分为 0，不再加分。判定使用当前格式的属性免疫表：标准 Gen5／Gen6 不启用，标准 Gen7～Gen9 及 PokeMMO 启用。PokeMMO 随机对战和 OU／UU／NU 的启动规则采用运行时 `gen = 8`，不能仅凭格式名称中的 Gen5 判断。自身强化、保护、天气、场地、撒钉及针对队友的招式不受此免疫影响。

### 睡眠条款检查 (Sleep Clause) (-20)

**基于**: CFRU battle_util.c:2018-2037 (DoesSleepClausePrevent)

PokeMMO 分级和随机对战复用 `Stadium Sleep Clause`：目标一方已有存活的睡眠精灵时，阻止对手再次催眠，Rest 自眠也计入；醒来或倒下后可再次催眠。主动使用 Rest 不受条款限制。普通 `Sleep Clause Mod` 对自眠的处理不同，不能将两种规则混同。

| 情况 | 扣分 | 说明 |
|------|------|------|
| 对手已有睡眠精灵 | -20 | 对手队伍中有**未倒下**的睡眠精灵时，睡眠招式会失败 |
| 对手无睡眠精灵 | 0 | 可以正常使用睡眠招式 |
| 睡眠精灵已倒下 | 0 | 已倒下的精灵不计入睡眠条款 |

**检查顺序**:
1. 目标已有状态 → -20 (优先检查)
2. **睡眠条款违规** → -20 (对手已有睡眠精灵)
3. 电气场地阻止睡眠 → -10
4. 特性阻止 (Vital Spirit/Insomnia/Sweet Veil/Comatose) → -20
5. 草系免疫粉末招式 → -20
6. Safety Goggles 阻止粉末 → -20

**适用招式**: Spore, Sleep Powder, Hypnosis, Sing, Grass Whistle, Lovely Kiss, Dark Void, Yawn, Relic Song

**实现**: `checkSleepMove` 检查 `state.opponent.team` 中所有精灵，查找 `!fainted && status === 'slp'`

### Magic Guard 状态招式检查 (-10)

对有 Magic Guard 特性的对手使用依赖持续伤害的状态招式会扣分：

| 招式 | 扣分 | 例外 |
|------|------|------|
| 鬼火 (Will-O-Wisp) | -10 | - |
| 剧毒 (Toxic) | -10 | 攻击方有 Venoshock 则不扣分 |
| 普通毒 | -10 | 攻击方有 Venoshock 则不扣分 |

**说明**: Magic Guard 使毒/烧伤的持续伤害无效，但如果攻击方有 Venoshock (毒击)，中毒状态仍有战术价值 (Venoshock 对中毒目标威力翻倍)。

### Covert Cloak 检查 (-3)

对持有 Covert Cloak (隐蔽斗篷) 的对手使用有附加效果的招式会扣分：

| 条件 | 扣分 |
|------|------|
| 招式有附加效果 (secondaryChance > 0) | -3 |
| 招式无附加效果 | 0 |

**受影响招式示例**:
- 十万伏特 (10% 麻痹)
- 冰冻光束 (10% 冰冻)
- 喷射火焰 (10% 灼伤)

### Salt Cure 检查 (-8~-10)

| 情况 | 扣分 |
|------|------|
| 目标已有 Salt Cure 状态 | -10 |
| 目标有 Magic Guard | -8 |
| 目标有替身 | -8 |

**说明**: Salt Cure 是 Gen 9 招式，40 威力但附加持续伤害状态。虽然 CFRU 没有实现此招式，但评分逻辑参考 CFRU 的 Leech Seed 模式。

### 强化招式浪费

| 当前等级 | 剑舞加分 |
|---------|---------|
| +0 | +10 |
| +2 | +5 |
| +4 | +2 |
| +6 | 0 (无法再提升) |

**HP 限制**:
- HP ≤ 25%: 不强化
- HP ≤ 40% 且较慢: 不强化
- HP ≤ 40%: -11 惩罚
- HP ≤ 60%: -6 惩罚

### 腹鼓检查 (-5~-100)

| 情况 | 扣分 |
|------|------|
| HP ≤ 50% | -100 (失败) |
| 唱反调特性 | -100 (反效果) |
| 50% < HP ≤ 70% | -5 (风险) |

### Counter/Mirror Coat 检查 (-3~-10)

招式类别判断使用已公开招式与相容 preset 候选；尚未公开的招式不视为不存在。只有完整配招或完整候选范围能排除对应攻击类别时，才判定“没有物理／特殊攻击”。反击伤害优先根据上一招估算，否则参考相容的对应类别攻击，并使用当前天气与场地。

| 招式 | 情况 | 扣分 |
|------|------|------|
| Counter | 对手无物理招式 | -10 |
| Counter | 对手是耐久型 | -3 |
| Mirror Coat | 对手无特殊招式 | -10 |
| Mirror Coat | 对手是耐久型 | -3 |
| Metal Burst | 先手 (会失败) | -10 |

### 重复设置 (-10)

- 天气已是目标天气
- 地形已是目标地形
- 隐形岩已存在
- 撒菱已满层
- 光墙/反射壁已激活
- 极光幕已激活或天气不是冰雹/雪

### Protect 连续使用扣分 (-20)

简化逻辑：如果上回合使用了 Protect 类招式，本回合再次使用则扣 20 分。

**受影响招式**:
- Protect, Detect, King's Shield, Spiky Shield
- Baneful Bunker, Obstruct, Silk Trap, Burning Bulwark, Endure

**不受影响招式** (可无限使用):
- Quick Guard, Wide Guard, Crafty Shield

| 条件 | 扣分 |
|------|------|
| 上回合使用了 Protect 类招式 | -20 |

**注意**: 切换后 lastMove 会重置为空，因此切换后使用 Protect 不会扣分。

| HP | 回复招式扣分 |
|----|------------|
| > 80% | -20 |
| > 70% | -5 |
| > 60% | -2 |

### 接触招式风险 (-1~-5)

对带有接触特性/道具的对手使用接触招式会有惩罚：

| 特性/道具 | 效果 | 扣分 |
|----------|------|------|
| 铁刺/粗糙皮肤 | 造成 1/8 伤害 | -2~-5 |
| 静电 | 30% 麻痹 | -2 |
| 火焰之躯 | 30% 灼伤 | -2 |
| 毒刺 | 30% 中毒 | -2 |
| 木乃伊 | 替换特性 | -1~-5 |
| 爆裂尸体 | 灭亡之歌效果 | -5 |
| 凸凸头盔 | 造成 1/6 伤害 | -2~-5 |

**免疫条件**:
- Magic Guard 免疫伤害类接触效果
- Protective Pads 免疫所有接触效果
- 属性免疫 (电系免麻痹、火系免灼伤)

### 双打队友检查 (-5~-25)

**扩散招式伤害队友** (v1.1.20 更新):

根据实际伤害百分比缩放扣分:

| 情况 | 扣分 |
|------|------|
| 会击杀队友 | -25 |
| 伤害 > 50% HP | -15 |
| 伤害 > 25% HP | -10 |
| 低伤害 / 信息不足 | -5 |

**其他队友攻击**:

| 情况 | 扣分 |
|------|------|
| 攻击队友 (无特殊理由) | -15 |
| 对队友用有害状态招式 | -100 |

**例外** (不扣分):
- 队友有吸收特性 (蓄电/储水/引火/食草/飘浮/食土)

Knock Off (拍落) 是恶系物理招式，65 威力，可以拍掉对手道具并在对手持有道具时伤害 ×1.5。

| 条件 | 加分 |

| 条件 | 扣分 |
|------|------|

## 黑雾 Haze

`negatives.ts` 的 `checkHaze` 处理无收益和占用回合的扣分，`positives.ts` 的 `rewardHaze` 奖励全场净收益。两者通过 `allNegativeScorers` / `allPositiveScorers` 接入通用评分流程，单打、双打和 Multi 共用。只统计场上存活精灵，包括使用者和队友；分数与传入的单个目标无关，不累加不同目标的评分。

| 能力等级绝对值 | 清除价值 |
|---|---:|
| 1 | 5 |
| 2 | 20 |
| 3 | 28 |
| 4 | 36 |
| 5 | 44 |
| 6 | 52 |

`净收益 = 清除敌方强化 + 清除己方下降 − 清除己方强化 − 清除敌方下降`，七项能力分别计分。

- 全场能力等级为零：最终 0 分，标记 `hasNoEffect`。
- 有能力变化但净收益不大于零：最终 0 分，不标记无效果。
- 净收益大于零：最终分数为 `min(140, 80 + 净收益)`，其中包含占用回合的 -20 分。

其余能力等级均为零时，对手攻击 +1 为 85 分，龙舞一次为 90 分，剑舞一次为 100 分，龙舞两次为 120 分，龙舞三次为 136 分。对手龙舞两次且己方队友攻击 +2 时为 100 分。日志记录回合成本，以及包含双方强化和下降四项分值的净收益；净收益奖励上限为 60 分。

`-clearallboost` 清零双方能力等级，后续请求中的黑雾评分随之归零。初版对七项能力使用相同价值表，不预测本回合的强化，也不按招式配置调整各能力的权重。

## 换人逻辑

### 主动换人触发条件

未被困住且有可用替补时，先检查能否先手击杀：场上只剩一个对手，且存在本回合可生效的攻击招式，能够先手并以平均伤害达到对手当前 HP，就留场，不考虑命中率。先手比较包含已暴露及 preset 候选招式的先制度、速度、顺风与戏法空间；速度相同不视为确定先手。两个对手同时在场时，不因能击杀其中一个就跳过承伤判断。

不满足上述留场条件时，满足以下条件之一就考虑换人：
- 最高攻击招式得分 <= 95，且最高状态招式得分 <= 90。
- 当前精灵的承伤威胁 >= 70%，即使存在高评分招式也会考虑换人。

```text
先手且平均伤害 >= 唯一对手当前 HP → 留场
否则：threat = max(对手威胁候选招式的平均伤害) / 当前 HP
考虑换人 = (attack <= 95 and status <= 90) or threat >= 0.7
```

伤害复用 CFRU `calculateDamage`，使用当前场地、能力等级、特性和道具信息。对手能力值沿用 preset；未命中时按 31 IV、85 EV、无性格修正估算。己方使用 request 中的实际能力值与当前 HP。多个存活对手取最大单招威胁，不累加集火伤害；群攻沿用伤害计算的多目标修正。平均伤害达到当前 HP 表示存在击倒风险，不代表最低伤害也必杀。

### preset 常用招式

`data/npc/opponent-presets.json` 由用户维护，可选 `moves` 数组填写招式 ID 或英文名，允许省略、为空或只填一两个。招式知识分别保存已暴露招式、尚未证实的候选和剩余槽数。实露不足四个不同招式时，各个「已暴露招式 ∪ preset 招式」分别参与承伤威胁计算，规范化名称后去重；这不是完整配招，不能认为候选同时占据剩余槽。实露四招及以上时，只使用真实暴露招式。当前世代尚不存在的预设招式和道具不参与估计。无已知攻击且无预设攻击时，威胁为 0。

候选合并用于先手击杀检查、70% 主动换人触发和 40% 替补准入。`BattleTracker`、对手的 `moves`、原有替补评分及再来一次／定身法等招式判断仍使用真实信息。preset 不填充剩余技能槽，不预测本回合选择。

通用数据参考 gen4／5／6／7／9 OU 和 gen5／6／7 UU，按图鉴编号排序，`nameZh` 用于审核。普通形态和 Mega 形态是独立条目，只有公开进化后才切换。允许仅配置 `moves`；未指定能力值时保持 IV=31、每项 EV=85、性格无修正。显式配置 `evs` 表时，表中省略的项目为 0，保持已有能力值 preset 的语义。配置由进程首次使用时缓存，编辑文件后重启服务生效。

### Random Battle 配置识别

Normal 和 Hard 共用 `cfru/util/random-presets.ts`。随机格式优先读取对应生成器的配置，不使用 OU 的性格、努力值或核心技能先验。Gen9 单打读取单打池，Gen9 Multi／双打读取双打池；PokeMMO 单打和 Multi 复用 Gen5 的单打池。适配器也支持 Gen5／6／7 的角色配置格式。

根据公开形态、等级、原始招式、原生特性和原始道具排除不相容配置。消耗道具保留原始道具证据；戏法、特性替换等后天变化不作为原配置证据。Gen5 喷火龙公开剑舞后只保留 Setup Sweeper 配置，候选仍受剩余技能槽限制。普通形态的当前能力值和特性不因推断出 Mega 石而提前进化；Gen7 妙蛙花 78 级可以匹配 Mega 配置，84 级匹配普通配置。

配置展开使用独立的生成器实例复用选招、道具、特性和 IV／EV 规则，不接触对战随机种子、隐藏队伍或玩家请求。展开结果按格式和配置缓存；选招顺序组合过多时，使用同一角色技能池的四招组合上界，再执行生成器的特性、道具和能力值规则。这可能保留实际选招器不会选出的组合，因此不是完整成队概率模型。达到展开上限时保留角色范围，不能以未枚举到某配置为由将其排除。

Normal 使用代表性能力值和候选共同确定的道具／特性，并分别计算各相容配置下的攻击威胁；不把不同配置的招式拼成一套。Hard 在相同候选上继续进行行动预测和战术评估。无相容随机配置时保留公开信息，以随机能力值基线估算，不套用 OU 配置。推断不写回 `BattleTracker`。

### 替补准入

所有主动换人候选先通过 `threat <= 0.4` 的承伤过滤，再参与现有换人评分。准入条件同样适用于低招式评分触发和无可用招式的主动换人，威胁值不直接加减替补评分。没有合格候选时留场选择招式，无可用招式时使用挣扎。

例如，巨钳螳螂面对已暴露喷射火焰的喷火龙，达到 70% 威胁就考虑换人；替补只有在预计承伤不超过其当前 HP 的 40% 时才参与评分。全队残血且无人符合条件时留场行动。

倒下等被迫换人不受 40% 准入限制，继续在距最高分不超过 5 分的候选中随机选择。该机制不预测对手下一步，不计算换入钉子损耗，也不进行多回合搜索。

**阈值设计依据** (基于负面评分分析):

| 攻击场景 | 扣分计算 | 分数 | 是否触发 |
|---------|----------|------|----------|
| 本系被单抵抗 | 100 + 3(STAB) - 5(resist) | 98 | 否 (STAB 抵消) |
| 非本系单抵抗+低伤 | 100 - 5 - 3 | 92 | **是** (弱势) |
| 非本系单抵抗+极低伤 | 100 - 5 - 8 | 87 | **是** (弱势) |
| 本系双抵抗 | 100 + 3 - 20 | 83 | **是** (双抵太严重) |
| 非本系双抵抗+极低伤 | 100 - 20 - 20 | 60 | **是** (明显弱势) |

| 状态场景 | 扣分计算 | 分数 | 是否触发 |
|---------|----------|------|----------|
| 正常使用 | 100 + 正面加分 | 100+ | 否 |
| 对手已有状态 | 100 - 10~15 | 85~90 | **是** (无用) |
| Magic Guard 毒/烧伤 | 100 - 10 | 90 | **是** (无效) |
| 特性免疫/魔法镜 | 100 - 20 | 80 | **是** (完全无效) |

```
关键设计:
- 攻击阈值 95: 允许小扣分(单抵抗)，惩罚大扣分(双抵抗+低伤害)
- 状态阈值 90: 对手已有状态时触发，正常状态招式不触发
- 能先手且平均伤害足以击杀唯一对手时留场；否则招式评分同时弱势或承伤威胁达到 70% 时，考虑换人
```

### 换人评分 (v1.1.26 更新)

```
换入得分 = 属性防御分 + 属性进攻分 + HP分 + 危险惩罚
```

物种属性和换人属性相克使用当前格式的 Dex。免疫单独通过 `getImmunity` 判断，`getEffectiveness` 返回的 `0` 表示中性伤害；双属性中的中性属性不抵消另一属性的弱点或抗性。自身、替补及公开对手的物种数据也遵循当前格式，例如 MMO 的 Granbull 为一般系。

**属性防御分**:
| 条件 | 加分 |
|------|------|
| 免疫对手已知招式 | +12 |
| 抵抗对手已知招式 | +6/招式 (最多 2 招) |
| 被对手招式克制 | -5 (HP<60%) 或 -8 (≥2招克制) 或 -10 (低HP且克制) |
| 被对手本系属性克制 | -3 (额外) |

**属性进攻分**:
| 条件 | 加分 |
|------|------|
| 有本系克制对手的招式 | +8 |
| 有克制对手的招式 (非本系) | +4 |

**HP分**:
| 条件 | 加分 |
|------|------|
| HP 百分比 | / 10 (0-10 分) |
| HP ≥ 80% | 日志标记 "High HP" |

**换入决策**:
- 通过 40% 准入的最佳换入得分 > 5 → 执行主动换人
- 无合格候选或最佳换入得分 ≤ 5 → 不换人 (继续使用当前招式)

## 对手信息处理

### 已知 vs 未知

| 信息 | 获取时机 | 未知时处理 |
|-----|---------|----------|
| 属性 | 上场时 | 从 Dex 查询 |
| 特性 | 特性触发时 | 空字符串，不扣分 |
| 道具 | 道具效果时 | 空字符串，不扣分 |

**重要**: 只有对手特性/道具被揭示后才会扣分！

### 示例

```
回合 1: 对手电龙上场，特性未知
→ AI 使用十万伏特，不会因蓄电扣分

回合 2: 十万伏特触发蓄电回复
→ BattleTracker 记录 ability = "voltabsorb"
→ 之后电系招式会扣 20 分
```

## 双打特殊处理

### Multi 共用决策

线上 `NPCMultiManager` 负责汇总四人对战的请求和公开信息，通过 `NormalAI.receiveRequestWithState` 对 p2 / p4 分别决策。两者共用招式评分、原始招式编号、目标位置、主动换人和被迫换人逻辑。

场上位置固定为 p2 = 1、p4 = 2，对手为 p1 = 1、p3 = 2。玩家的请求仍只包含自己的队伍，换人候选排除场上及倒下精灵；队友和队友的后备不会进入自己的候选。p2 / p4 同时选择 `switch 2` 表示分别换入各自队伍的第二只精灵。

己方精灵复用 `buildPokemonFromRequest` 读取当前特性、等级及实际能力值，再从 `p2a` / `p4b` 的 tracker 记录补充能力等级、特性能力值修正和上次招式。等待中的存活队友也参与黑雾、群攻及辅助招式评估。辅助目标根据队友实际位置生成：p2 指向 `-2`，p4 指向 `-1`。

普通行动等待双方请求或同回合明确的 `wait` 请求，双方决策完成后才发送指令；队伍预览和被迫换人可以独立处理。测试 `test/server/npc/multi-decisions.js` 覆盖线上协调器及完整四人对战，AI 无权读取模拟器内部 `Battle` 对象。

### 攻击方识别

双打时每只精灵需要独立做出决策。使用 `activeIndex` 参数标识当前行动的精灵：

```
request.active[0] → activeIndex = 0 → 第一只精灵
request.active[1] → activeIndex = 1 → 第二只精灵
```

招式和换人评估均按 `slot === activeIndex + 1` 查找行动精灵。队友倒下后，过滤后的 `self.active` 数组索引不代表场上位置。

### 换人候选与判断

主动换人候选排除 `request.active.length` 个场上位置、标记为 `active` 的精灵、倒下的精灵和本回合队友已选择的替补。被困住时不主动换人。

留场价值取当前精灵对所有存活对手的最高招式评分；一个对手免疫时，仍会考虑攻击另一个对手。承伤威胁取所有存活对手威胁候选攻击的最大值，达到 70% 可以独立触发换人考虑。主动换人先执行 40% 准入过滤；合格替补分别对所有存活对手评分，并以最差对局得分比较。被迫换人共用替补评分，不执行承伤准入。

被迫换人请求通过 `forceSwitch.length` 保留双打状态和两个对手。招式评分全为零时，仍保留已评估的目标位置与招式目标类型，避免固定选择已经倒下的第一目标。

### 多目标评估

对于单体攻击招式，AI 会评估所有对手并选择最优目标：

```
招式评估流程 (双打):
    │
    ▼
遍历所有对手
    │
    ├─ 对手 1: 评分招式
    ├─ 对手 2: 评分招式
    │
    ▼
选择得分最高的 (招式, 目标) 组合
    │
    ▼
返回招式和目标位置 (bestTargetPos)
```

**选择逻辑**: NormalAI 选择**对任一目标分数最高的招式**，而不是计算群攻总伤害。这与 BasicAI 不同。

**群攻招式多目标 KO 奖励** (v1.1.21):

群攻招式会为**每个被击杀的对手**获得独立的 KO 奖励：
- 第一个目标的 KO 奖励: 由 `rewardKnockout` 处理 (+20)
- 其他目标的 KO 奖励: 由 `rewardSpreadMove` 处理 (+20 per KO)

```
群攻招式额外奖励:
- 基础群攻: +6 (命中多目标) - 仅当对其他对手有效时
- 额外 KO: +20 (每个额外被击杀的对手)
- 先手双杀: +5 (安全性奖励)
- 额外 2HKO: +6
- 额外中等伤害: +3 (30%+ HP)
```

**v1.1.22 优化**: 基础群攻 +6 奖励仅在招式对**至少一个其他对手**有效时给予（有效定义：effectiveness > 0 且伤害 >= 15% HP）。这避免了对第二个对手免疫时仍给予群攻奖励的问题。

**示例 - 群攻 KO 两个对手 + 击杀队友**:
```
地震 vs 对手A (可击杀) + 对手B (可击杀) + 队友 (会被击杀):

评分:
100 (基础分)
+20 (KO 对手A - rewardKnockout)
+5  (先手 KO - rewardKnockout)
+6  (群攻命中多目标 - rewardSpreadMove)
+20 (KO 对手B - rewardSpreadMove)
+5  (先手双杀 - rewardSpreadMove)
-25 (击杀队友 - checkSpreadMoveHitsPartner)
= 131 分 (值得使用)

相比之前 (v1.1.20):
100 + 20 + 5 + 6 - 25 = 106 分 (低估了第二个 KO 的价值)
```

**示例 - 群攻 KO 一个对手，另一个免疫 + 击杀队友** (v1.1.22):
```
地震 vs 对手A (可击杀) + 对手B (飞行，免疫) + 队友 (会被击杀):

评分:
100 (基础分)
+20 (KO 对手A - rewardKnockout)
+5  (先手 KO - rewardKnockout)
+0  (无群攻奖励 - 对手B 免疫)
-25 (击杀队友 - checkSpreadMoveHitsPartner)
= 100 分

铁头 vs 对手B (50% 伤害):
100 (基础分)
+5  (中等伤害 - rewardHighDamage)
+3  (STAB)
= 108 分 ★

选择: 铁头 (108 > 100)
虽然地震能 KO 对手A，但对手B 免疫导致这实际是"单目标 KO + 杀队友"，
不如单体招式打有效目标。
```

**示例**:
```
龙头地鼠招式评估:
- 地震 vs 炽焰咆哮虎: 117 分 ★ (克制+4, STAB+3, 2HKO+8, 群攻+6, 打队友-10)
- 地震 vs 甜茶壶: 92 分 (抵抗-2, 低伤害-5, STAB+3, 群攻+6, 打队友-10)
- 岩崩 vs 炽焰咆哮虎: 112 分 (克制+4, 群攻+6)
- 岩崩 vs 甜茶壶: 101 分 (低伤害-5, 群攻+6)
- 铁头 vs 甜茶壶: 101 分 (STAB+3, 低伤害-2)

最高分: 地震 vs 炽焰咆哮虎 = 117
选择: 地震
```

**群攻招式** (如地震、冲浪) 对所有对手分别评分，选择最高分。群攻额外获得 +6 分 "Spread move hits multiple targets" 加成，但会打到队友时扣 -10 分。

### 目标位置格式

Pokemon Showdown 双打目标位置格式：
- `1`, `2` = 对手位置
- `-1`, `-2` = 队友位置
- `0` = 无特定目标

### 队友判断

使用**对象引用比较**判断目标是否为队友，而非 slot 数字比较（因为 slot 数字在双方可能相同）：

```typescript
// 正确
const isPartner = state.self.active.some(p => p === target);

// 错误 (slot 可能重复)
const isPartner = state.self.active.some(p => p.slot === target.slot);
```
