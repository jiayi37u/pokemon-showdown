# v1.1 需求文档

## 目标

实现 CFRU (Complete-Fire-Red-Upgrade) 评分系统，让 NPC AI 能够综合评估招式价值，包括伤害、状态招式、强化招式。

---

## 背景

### v1.0 的局限性

v1.0 的 BasicAI 存在以下问题：

1. **只考虑伤害**: 无法评估状态招式（睡眠、麻痹）和强化招式（剑舞、龙舞）
2. **伤害计算不准确**: 不考虑能力变化、特性、道具、天气
3. **不主动换人**: 即使场上精灵不利也不换人
4. **无对手信息**: 无法追踪对手的能力变化、特性、道具

**用户反馈**:
```
BasicAI 会疯狂使用低伤害招式，无视对手已经强化到 +6。
AI 从不使用催眠粉这种强力的状态招式。
对手明显被克制，AI 也不换人。
```

### CFRU 评分系统

CFRU 是 GBA 宝可梦火红版的完整升级项目，包含成熟的 AI 系统：

**核心文件**:
- `ai_util.c`, `damage_calc.c` - 伤害计算工具
- `ai_negatives.c` - 负面评分（扣分规则）
- `ai_positives.c` - 正面评分（加分规则）
- `ai_switching.c` - 切换决策
- `ai_advanced.c` - 战斗风格、招式预测
- `ai_partner.c` - 双打协作

**v1.1 目标**: 移植 M1-M4（评分引擎），M5-M10 推迟到后续版本。

## 里程碑规划

### M1: 工具函数 (ai_util.c, damage_calc.c)

**目标**: 实现 CFRU 的伤害计算和速度比较。

**功能需求**:

| 功能 | CFRU 函数 | 优先级 |
|------|-----------|--------|
| 完整伤害计算 | `AI_CalcDamage()` | P0 |
| 多段攻击期望 | `GetNumHitsBasedOnMove()` | P0 |
| 速度比较 | `AI_WhoStrikesFirst()` | P0 |
| 额外伤害 | `GetSecondaryEffectDamage()` | P1 |
| 重量招式威力 | `GetActualSpeciesWeight()` | P2 |

**验收标准**:
- [ ] 支持所有主要特性（大力士、厚脂肪、Multiscale 等）
- [ ] 支持所有主要道具（讲究系列、生命宝珠、专爱围巾）
- [ ] 多段攻击正确计算期望次数

### M2: 负面评分 (ai_negatives.c)

**目标**: 实现 CFRU 的扣分规则，避免使用无效招式。

**功能需求**:

| 分类 | 检查项 | 优先级 |
|------|--------|--------|
| 免疫检查 | 属性免疫、神奇守护、特性免疫 | P0 |
| 抵抗扣分 | 0.5x / 0.25x 克制 | P1 |
| 低伤害扣分 | < 10% / 20% / 33% HP | P1 |
| 状态失效 | 已有状态、特性阻止、场地阻止 | P0 |
| 强化满级 | 能力已 +6 / -6 | P0 |
| 回复浪费 | HP > 60% / 70% / 80% | P1 |
| 双打队友伤害 | 误伤队友检查 | P0 |
| 重复设置 | 光墙/反射壁/隐形岩已存在 | P1 |

**验收标准**:
- [ ] 不会对免疫目标使用招式
- [ ] 不会在能力满级时继续使用强化招式
- [ ] 不会在 HP 90% 时使用回复招式
- [ ] 双打谨慎用伤害招式攻击队友

### M3: 正面评分 (ai_positives.c)

**目标**: 实现 CFRU 的加分规则，识别高价值招式。

**功能需求**:

| 分类 | 加分项 | 优先级 |
|------|--------|--------|
| 伤害评估 | 击杀 (+20)、高伤害 (+2~+10) | P0 |
| 克制加分 | 2x (+4~+8)、4x (+15) | P0 |
| STAB | 本系招式 (+3) | P0 |
| 状态招式 | 睡眠 (+16~+20)、麻痹 (+12~+16) | P0 |
| 强化招式 | 龙舞/腹鼓 (+15)、剑舞 (+12) | P0 |
| 防御强化 | 宇宙力量/铁壁 (+8~+12) | P1 |
| 入场伤害 | 隐形岩/撒菱/毒菱 (+10~+15) | P1 |
| 控制招式 | 挑衅/定身法/再来一次 (+8~+10) | P2 |

**验收标准**:
- [ ] 能够识别击杀机会（KO 优先）
- [ ] 睡眠招式得分 > 普通攻击招式
- [ ] 强化招式在合适场景下得分最高
- [ ] 入场伤害在对手未设置时得分较高

### M4: NormalAI 整合

**目标**: 整合 M1-M3，实现完整的 NormalAI。

**功能需求**:
- [ ] 集成评分引擎
- [ ] 实现换人决策（基础版）
- [ ] 支持单打和双打
- [ ] 日志系统（可配置详细程度）
- [ ] 支持自定义难度选择

**验收标准**:
- [ ] AI 能够合理选择攻击/状态/强化招式
- [ ] AI 能够在不利场景下换人
- [ ] 双打能够正确选择目标
- [ ] 测试覆盖率 > 90%

## 范围限制

### v1.1 不包含的内容

以下 CFRU 功能推迟到后续版本：

| 功能 | CFRU 文件 | 推迟原因 | 计划版本 |
|------|-----------|---------|---------|
| 完整切换决策 | ai_switching.c | 需要场景评估逻辑 | v1.2 (M5) |
| 战斗风格识别 | ai_advanced.c | 需要对手行为分析 | v1.2 (M6) |
| 招式预测 | ai_advanced.c | 需要历史数据追踪 | v1.2 (M7) |
| 双打协作 | ai_partner.c | 需要队友协调逻辑 | v1.3 (M9) |

### v1.1 简化的部分

1. **换人决策**: 基于评分阈值的简单换人，不包含 CFRU 的完整切换评估
2. **对手能力估算**: 使用固定值（IV=31, EV=85），不进行动态推断
3. **招式预测**: 不预测对手下一步行动

## 技术挑战

### 挑战 1: 服务端架构限制

**问题**: AI 运行在主进程，无法访问子进程的 `Battle` 对象。

**影响**: 无法直接获取对手精灵信息（属性、特性、能力变化）。

**解决方案**: 实现 `BattleTracker`，通过监听协议消息追踪对手状态。

**协议消息示例**:
```
|switch|p1a: Alakazam|Alakazam, L50|100/100     # 对手上场
|-ability|p1a: Alakazam|Magic Guard             # 特性暴露
|-boost|p1a: Alakazam|spa|2                     # 能力变化
|move|p1a: Alakazam|Psychic|p2a: Pikachu       # 使用招式
```

### 挑战 2: CFRU 代码移植

**问题**: CFRU 是 C 语言，使用大量宏定义和全局状态。CFRU不包含Gen9技能、特性、道具等处理。

**影响**: 无法直接翻译，需要重新设计数据结构。Gen9机制无法体现在评分系统。

**解决方案**:
- 将 CFRU 的全局变量转换为 `BattleState` 对象
- 将 CFRU 的宏定义转换为 TypeScript 函数
- 保留 CFRU 的评分逻辑和阈值
- Gen 9 特有特性/招式单独处理

## 风险与缓解

### 风险 1: CFRU 迁移不完整

**风险**: 遗漏 CFRU 的特殊情况处理，导致 AI 行为异常。

**概率**: 中
**影响**: 高

**缓解措施**:
- 创建 CFRU 迁移对照清单
- 逐函数对照实现
- 编写完整的测试用例

### 风险 2: 双打复杂性

**风险**: 双打的目标选择、队友保护逻辑复杂，容易出错。

**概率**: 高
**影响**: 中

**缓解措施**:
- 优先实现单打
- 双打单独测试
- 参考 CFRU ai_partner.c
