# Hard 用终点评分上界减少完整计算

## 提前排除条件

目标是用更少计算确定与同一候选树完整搜索相同的行动。对于状态转移已经完成、尚未评估对位的终点，可以先用物料与价值函数各项的范围推导上界：

```text
上界 = 双方可入场成员的物料价值差
     + 己方可入场成员数 × (15 + 45 + 30 + 10)
     + 己方可入场且在场成员数 × 35
```

物料项为每只成员的 `25 + 35 × 入场后 HP / maxHP`。15 是己方进攻压力最大贡献；45、30、10 是对方缺少 check、counter 和持续防守答案时的最大损失；35 是对当前威胁缺少即时应对的最大损失。完整估值与上界使用同一组现有系数。

只要某个公共后续行动已完整计算，其价值就是可执行下界。另一个行动即使按上述最乐观终点估值汇总也无法超过它，就不必计算这些终点的完整对位矩阵。仍有可能胜出或并列的行动继续展开。这省去了尚未进行的计算，并非仅命中已有缓存。

上界复用入场和延迟攻击处理。搜索首先判断原状态是否终局；估值内部结算延迟攻击后不另加终局判断，以保持现有估值口径。未展开的补位检查点保留无穷；配置权重、最坏回应和公共信息组共享补位沿用既有聚合规则。

## 被舍弃的方案

在后续行动内部调整回应顺序、优先覆盖不同配置，在 Slowbro、Alakazam、Serperior、011 T10 四个快照上都没有减少节点。该层通常已经绑定单个配置，调整顺序没有解决实际计算瓶颈，因此未采用。材料：`/tmp/hard-continuation-coverage/REPORT.md`。

## 验证边界

`prune: false` 使用同一候选树完整展开，回归检查行动一致及上下界有效性。新增测试覆盖无需评估完整对位的有限叶界、未知检查点、胜负和平局终局，以及延迟攻击结算不变异输入。全部 NPC 回归为 1680 passing、1 pending；TypeScript、ESLint 与 diff 检查通过。

该上界将所有未知对位都放宽到极端有利，可能过松。减少节点不必然带来同比例耗时下降：计算上界也有成本，完整估值的缓存命中情况不同。是否保留应结合冻结模块的同快照对照，不用胜率代替效率验证。

## 缓存格收紧上界试验

独立扫描已缓存 Pair、对未知格填单调极值的方案未采用。Alakazam 节点 3047 → 3024，但耗时 10.97 → 11.03 秒；011 节点 25689 → 25380，但耗时 52.56 → 53.39 秒。011 为此进行了 2321 次上界估值，读取 62250 个已知格，仅少算 309 个叶节点。该试验说明减少节点不足以证明整体效率改善；额外构造配置、键和汇总矩阵的成本不可忽略。18 个 HP／入场状态的保守性校验通过，仍不据此采用没有耗时收益的方案。材料：`/tmp/hard-cached-pair-upper/REPORT.md`。
