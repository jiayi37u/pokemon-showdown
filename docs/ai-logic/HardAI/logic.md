# Hard AI

Hard 是独立难度，沿用公共伤害计算与评分引擎，增加 CFRU 的角色识别、招式预测和战术换人。Normal 的规则注册、权重与换人阈值固定；公共状态追踪的正确性修复仍适用于所有难度。界面和 `/npc` 命令使用 `hard`，Normal 的界面名称仍是 Smart，CLI 使用 `normal`。

## 文件职责

- `server/npc/ai/hard.ts`：请求入口、候选行动、目标选择、日志与换人冷却。
- `server/npc/ai/hard/opponent-model.ts`：角色识别、基于已知招式与 preset 的对手行动预测、格式专属招式数据。
- `server/npc/ai/hard/evaluation.ts`：Hard 的招式价值与换人评估。挑衅、回复、保护、强化等规则集中在这里，不按招式拆文件。
- `server/npc/ai/cfru/`：公共状态、追踪、计算和基础评分。Hard 用 `setScorers` 替换强化、回复、挑衅、轮转、开墙的正面奖励，再加入自己的战术判断；Normal 继续注册原规则。
- `server/npc/ai/multi-manager.ts`：根据难度创建 Normal/Hard 控制器，合并双方公开信息，限制每个控制器只能换入自己队伍的后备。

## 观察和预测

`BattleTracker` 只记录协议事实：公开身份、招式、最后行动、能力变化、道具、场地、临时状态和回合。临时状态支持 `-start` / `-end`，换人时清除；Multi 不同玩家的同种宝可梦分别记录。`itemKnown` 区分已确认道具和 preset 假设。tracker 同时记录公开队伍人数、Mega 形态变化、入场后行动和祈愿等待回合，不为未出场队员编造身份。

通用配置存放在 `data/npc/opponent-presets.json`，参考 gen4／5／6／7／9 OU 和 gen5／6／7 UU 配置凝练为 374 个条目，按图鉴编号排序并包含 `nameZh`。每种形态保留一份常见能力值和核心招式；难以确定的字段可以省略，道具未知不等于没有道具。Normal 直接消费通用配置。

gen7 OU 的详细配置存放在项目内的 `data/npc/strategies/gen7ou.json`，覆盖 104 种形态、174 套配置。`gen7ou` 和 `gen7customgame` 使用该数据；Hard 在没有对应分级、没有对应精灵或没有相容配置时，统一回退到通用配置。数据保留来源信息，不依赖外部仓库或网络。

普通形态和 Mega 形态分别匹配各自条目；对手公开 Mega 进化前始终按普通形态估计，不因猜测 Mega 石而提前切换形态、能力值或招式配置。

Random Battle 优先使用与 Normal 共用的随机配置识别，读取当前格式的生成器及技能池，结合公开等级、招式、道具和特性缩小范围。双方共用确定性的配置排除；Hard 保留各相容配置的能力值、道具和特性假设用于战术判断。生成器展开上限和保守组合范围见 [Normal 的随机配置说明](../NormalAI/logic.md#random-battle-配置识别)。随机格式不使用 OU 能力值先验。

Hard 根据已展示招式、原始道具和原生特性筛选配置。招式必须能分配到不同槽位，不能把同一槽的两个候选当成两招；四招全部公开后不再添加第五招。觉醒力量保留属性候选，Mega 形态筛选相应 Mega 石。消耗道具的公开记录保留原始道具，戏法等后天获得的道具不作为原配置证据。Z 攻击、间接调用的招式和挣扎不记录为原始招式槽。

每个相容配置保留自己的能力值、道具和特性估计，攻击、承伤和速度判断使用这些候选。各配置先验等权，同一配置的选项分摊其权重；这不是使用率或统计后验概率。通用配置回退仍以公开道具和消耗记录为准；缺少攻击信息且尚有未知招式槽时，参考可学的本系攻击作为威胁回退。

招式知识分为 `revealedMoves`、`presetCandidates`、`remainingSlots`。摔角鹰人公开挑衅和近身战后，剑舞、杂技、飞膝踢仍是候选，但只剩两个未知槽；组合判断不能同时假设三个候选都存在。Normal 分别计算各候选攻击的威胁，Hard 还约束招式共存和详细配置的槽位。预测评分只把已知招式和正在评估的候选传入基础评分器，不把五招当成一套配置。四招全部公开后仅保留公开招式。

通用配置会过滤当前世代尚不存在的招式和道具。未知道具不触发杂技威力翻倍或轻装加速；公开失去道具后可据此计算，轻装的生效记录在换下时清除。

预测参考 `ai_master.c:PredictMovesForBanks`，交换评分视角，按招式可用权重与分数差生成行动权重。全部低于 100 且公开信息表明仍有后备时，换人分支占 60%，攻击分支仍然保留。战术评分使用预期承伤；换入安全与强化风险取伤害分布的 85% 分位数和均值中的较大值。原生道具的讲究锁招与挑衅会限制各候选下的行动。推断不写回 tracker，不读取模拟器隐藏队伍或玩家已提交行动。

角色参考 `ai_advanced.c:PredictFightingStyle`，按招式组合与道具识别进攻、强化、消耗、撒钉、开墙、治疗、驱逐、接棒、空间、辅助。只有部分角色参与本阶段的评分调整，不能视为完整 CFRU 风格迁移。

## 决策

- 攻击结合预期承伤和出手顺序；先手击杀可抵消对应威胁。替身不会被当成可直接击杀本体。
- 回复考虑行动前承伤、实际可回复血量，以及回复后是否仍被击杀；光合作用、月光、晨光和集沙按天气计算回复量。
- 挑衅按预测变化招式、出手顺序和对手辅助能力加分，已处于挑衅状态的目标不重复使用。
- 保护考虑持续伤害、被动回复、祈愿到账、有效火焰宝珠／剧毒宝珠和哈欠的收益，降低连续保护与自身回合末倒下时的价值。
- 祈愿判断能否活到回复回合，并支持将回复传给能安全换入的受伤队友；队伍治疗判断异常是否有清除价值。
- 击掌奇袭仅在入场后的首次行动使用，无法行动也会消耗首次行动窗口。
- 开墙按预测攻击类别和能否避免击杀评分；替身评估血量成本与阻挡能力；驱逐考虑能力提升和钉子，最后一只对手不会触发撒钉收益。清除浓雾没有场地收益时扣分。
- 强化考虑预测换人和承伤空间，预测本回合会倒下时扣分。
- 主动换人先扣除入场钉子和预测攻击伤害，拒绝会立即倒下的后备。参考 CFRU 权重：击杀 +31、先手 +14、抵抗预测攻击 +17、两击击杀 +2、后续被击杀 -39，并增加入场损失惩罚。
- 换人条件覆盖灭亡之歌末回合、无法承受攻击、哈欠、自然回复、再生力、招式整体不利、主要攻击能力下降、无效讲究锁招、睡眠、持续伤害和保留受威胁进攻手。有可靠先手击杀或有价值的回复时优先留下。非紧急换人间隔至少 3 回合；倒下风险与灭亡之歌可跳过冷却。
- 强制换人考虑钉子与下一回合对位，不扣除不存在的本回合换入攻击。
- Mega 作为独立行动候选，使用形态属性、特性、天气和保守估计的能力变化；己方 request 不提供性格，进化前的能力变化估计不等同于精确模拟。
- 攻击型 Z 招式按原招式推导威力、分类和优先级，能产生新增击杀时提高收益，普通攻击已能击杀时保留资源。变化型 Z 招式不主动消耗资源。亲密度招式使用己方 request 中的实际威力。

## 迁移边界

来源是 `Complete-Fire-Red-Upgrade/src/Battle_AI/` 的 `ai_master.c`、`ai_advanced.c`、`ai_positives.c`、`ai_switching.c`。这是公开信息下的启发式适配，M5–M7 部分迁移，M8 入口可用。招式分数沿用项目尺度，不能与原 C 实现逐项等价。

尚未覆盖：依据伤害区间和速度顺序进一步约束 EV／性格、经过校准的配置概率、完整队伍胜负价值、多回合搜索、完整 CFRU 特例、变化型 Z／Ultra／极巨化／太晶化策略、双打联合行动。双打和 Multi 可以合法决策并使用已有基础队友检查，但按单个行动评分；承伤近似所有对手集中攻击当前宝可梦，不构成集火、掩护或行动组合优化。共用伤害计算器仍是近似模型，未知招式不足时预测会缺少威胁。

公开昵称是身份索引的一部分；同一玩家给同种宝可梦使用相同昵称、幻觉揭露等身份歧义仍需后续完善。临时状态追踪不等价于完整模拟器状态（例如接棒与特殊状态复制）。

## 验证

`test/server/npc/hard-ai.js` 覆盖先手击杀、替身、吸收换入、钉子、受困、灭亡之歌、哈欠与冷却、自然回复、回复时机、挑衅、强制替换、公开信息边界及 MMO 招式数据。通用配置回归覆盖 MMO／gen6 OU／gen7 OU／National Dex 的未出招格斗威胁、候选招式共存、道具未知和公开 Mega 形态切换。`multi-decisions.js` 验证 Hard 经生产协调器提交合法指令，`random-menu.js` 验证 Hard 菜单与 Multi 参数。

实战工具见 [模拟战斗说明](../../../test/npc/sim-battle/README.md)，使用 `--npc-difficulty hard`。runner 默认校验队伍并保留校验后的形态、特性等规范化结果；NPC 正式入口也使用规范化后的玩家队伍。

样例 gen7 OU 对照交换两套队伍与 AI 所在位置，每个种子四场。位置交换属于配对样本；结果用于观察行为，不代表所有队伍或分级的总体胜率。
```bash
node test/npc/sim-battle/compare.js 10 /tmp/npc-hard-comparison
```

输出目录保留每场协议和决策日志、错误输出，以及 `summary.json`。回合上限与真正的平局分别统计，不算作胜利。

验证包含默认 Mocha 套件、公共 AI 专用测试与 TypeScript 检查。`cfru-ai.js` 使用生产招式构造器与真实评分引擎覆盖 21 个回归场景，重复的属性相克和 tracker 测试由专用测试负责。MMO 数据检查仅允许已列明的数据依赖。

```bash
node node_modules/mocha/bin/mocha.js --exit --timeout 10000
node test/npc/ai/run-tests.js
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

只运行 NPC 回归时：

```bash
node node_modules/mocha/bin/mocha.js --no-config --exit --timeout 10000 \
  test/main.js 'test/server/npc/*.js'
```

公共正确性修复包括招式的 `status`、`boosts`、`recoil` 数据传递、毒液冲击识别，以及 Encore 的属性免疫查询；它们同时适用于 Normal 和 Hard，不调整难度权重。
