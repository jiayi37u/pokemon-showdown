# v1.0 需求文档

## 目标

为 Pokemon Showdown 实现 NPC 对战功能，允许用户与电脑控制的对手进行对战。

---

## 背景

### 问题陈述

Pokemon Showdown 原生只支持玩家对战 (PvP)，缺少 NPC 对战功能。用户需要：
1. 与电脑训练家对战来熟悉规则和测试队伍
2. 模拟道馆馆主/四天王等经典游戏体验
3. 在没有对手时也能进行对战

### 现有解决方案分析

其他 Pokemon 对战模拟器的 AI 实现：
- **Pokemon Showdown 官方**: 无 NPC 功能
- **CFRU (Complete-Fire-Red-Upgrade)**: GBA ROM Hack 项目，包含完整的 AI 系统

**选择**: 移植 CFRU 的 AI 逻辑，因为：
- 完整的评分系统
- 经过实战检验
- 支持多种 AI 难度

---

## 功能需求

### FR1: NPC 模板系统

**描述**: 允许定义多个 NPC 训练家，每个 NPC 有独立的队伍和难度配置。

**用户故事**:
```
作为玩家，我希望能够挑战不同的 NPC 训练家，
每个训练家有独特的名字、队伍和战斗风格，
这样我可以体验多样化的对战。
```

**验收标准**:
- [ ] 支持通过 JSON 文件定义 NPC 模板
- [ ] 每个 NPC 包含: ID、名字、难度、队伍文件路径
- [ ] 支持多个 NPC 模板

### FR2: BasicAI 智能

**描述**: 实现简单的 AI 决策逻辑，优先使用最大伤害的招式。

**用户故事**:
```
作为玩家，我希望 NPC 能够做出基本合理的决策，
不会使用明显无效的招式（如对免疫属性使用招式），
这样对战才有基本的挑战性。
```

**验收标准**:
- [ ] AI 能够计算招式伤害
- [ ] AI 会选择伤害最高的招式
- [ ] AI 检查类型免疫和特性免疫
- [ ] AI 不使用状态招式（v1.0 限制）
- [ ] AI 不主动换人（v1.0 限制）

### FR3: 聊天命令接口

**描述**: 提供聊天命令让用户发起 NPC 对战。

**用户故事**:
```
作为玩家，我希望能够通过简单的命令挑战 NPC，
而不需要复杂的配置或操作，
这样我可以快速开始对战。
```

**验收标准**:
- [ ] `/npc challenge <template>` 发起挑战
- [ ] `/npc list` 显示可用 NPC 列表
- [ ] 命令有清晰的错误提示

### FR4: 对战格式支持

**描述**: 支持主流对战格式。

**验收标准**:
- [ ] 支持单打 (Singles)
- [ ] 支持双打 (Doubles)
- [ ] 支持随机对战 (Random Battle)

---

## 非功能需求

### NFR1: 性能
- AI 决策时间 < 5 秒（普通对战）

### NFR2: 可扩展性
- 架构支持添加更多 AI 难度等级
- 支持添加新的 NPC 模板

### NFR3: 代码质量
- 使用 TypeScript 类型安全
- 遵循 PS 服务端代码风格

---

## 范围限制

### v1.0 不包含的内容

以下功能推迟到后续版本：

| 功能 | 推迟原因 | 计划版本 |
|------|---------|---------|
| 状态招式评估 | 需要复杂的评分系统 | v1.1 |
| 换人决策 | 需要场景评估逻辑 | v1.1-v1.2 |
| 战斗风格识别 | 需要对手行为分析 | v1.2 |
| 招式预测 | 需要历史数据追踪 | v1.2 |
| 双打协作 | 需要队友协调逻辑 | v1.3 |

---

## 成功指标

- [ ] 用户能够成功发起并完成 NPC 对战
- [ ] AI 不会出现明显的低级错误（如攻击免疫目标）
- [ ] 至少支持 3 个 NPC 模板
- [ ] 代码覆盖率 > 70%
